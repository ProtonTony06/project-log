---
title: "Spring WebSocket añade OriginHandshakeInterceptor por defecto y rechaza TODO Origin con lista vacía"
type: discovery
what: "AbstractWebSocketHandlerRegistration.getMappings() (spring-websocket 6.2.19) añade SIEMPRE un OriginHandshakeInterceptor tras los interceptores del usuario; su beforeHandshake hace isSameOrigin(request) || corsConfiguration.checkOrigin(origin) != null, y con la lista de orígenes del registro VACÍA (default) devuelve 403 para CUALQUIER Origin cross-origin — antes de llegar a los interceptores propios."
why: "En el smoke E7.9 el upgrade con Origin declarada y token VÁLIDO moría con 403 que nada del corte lanzaba: era el interceptor POR DEFECTO del registro, no el JwtHandshakeInterceptor. La pista clave fue el contraste de ramas: el MISMO Origin con token MALO daba 401 (el JwtHandshakeInterceptor corre PRIMERO en la cadena, rechaza antes de que el default mire el Origin), pero con token VÁLIDO el flujo continuaba hasta el default y ahí moría con 403 — el check 'inocente' vivía una capa por debajo."
where: "backend/src/main/java/com/projectlog/config/WebSocketConfig.java (fix: registro.setAllowedOrigins(frontendOrigin) SOLO con la propiedad non-blank, orígen EXACTO de CORS panel — jamás \"*\" ni setAllowedOriginPatterns); bytecode verificado con javap sobre spring-websocket-6.2.19.jar (AbstractWebSocketHandlerRegistration y OriginHandshakeInterceptor)."
learned: "1) El registro de HandlerMapping de WS de Spring no es neutral en CORS: la lista vacía NO significa 'sin filtro de Origin' sino 'rechazar todo Origin' (checkOrigin null → 403). 2) El diagnóstico efectivo fue la cadena: llamada directa al interceptor con mocks (descartar el propio) → upgrade real con dump de status/cabeceras (ACAO reflejado ⇒ un filtro CORS participaba) → socket crudo con variantes de Origin 101/403 → TRACE de org.springframework.web.socket que imprimió 'Handshake request rejected, Origin header value … not allowed' de OriginHandshakeInterceptor. 3) WebSocketHandlerRegistry NO tiene setAllowedOrigins: vive en WebSocketHandlerRegistration (lo que devuelve addHandler(...) — por eso el fix tipa la variable 'registro'). 4) Con la propiedad vacía (S26) el dueño del reject sigue siendo el JwtHandshakeInterceptor: la lista queda vacía y el default se mantiene (nunca se alcanza porque el interceptor propio responde 403 primero)."
